# dotOrcA 项目章程 V1.1（2026-11-26）

## 定位
独立自动视频压缩软件，不依赖 Film Grain Studio，不继承其历史代码或架构。用户无需视频编码知识。在不超过指定文件容量前提下尽可能保留画质，智能平衡质量和耗时。

## 技术选型
Rust + CUI v1.5.0（CPU 软件渲染，完整暗黑），Windows x64；便携单 EXE，外置编码器及数据。核心引擎、Benchmark、GUI 独立，前两者纯 Rust，GUI 允许薄 C FFI，GitHub Actions 自动构建测试。运行时不依赖 PowerShell、BAT、Python、.NET、WebView2。外部程序通过 Rust std::process::Command 直接传参，不走 Shell。此处取代 V1.0 的 Go/Fyne 选型，其余目标不变。

## UI
单窗口暗黑、拖放、批量任务。主要设置仅目标容量、目标视频编码格式、最大输出分辨率；其余自动决策。显示预计耗时、预计容量、实际路线、进度和最终压缩结果。首屏优先，后台复杂性不转嫁用户。

## 压缩策略
最终容量硬约束，在约束内追求最佳画质。支持固定容量或按每个原文件字节数的百分比（互斥，百分比表示目标保留比例）。源文件已不超过上限时直接跳过，不转码、不复制、不因指定编码或最大边而强制重编码。分析源视频时长、分辨率、帧率、格式及 HDR，计算音视频码率预算并选择编码参数。源视频长边不超过用户设定最大边时必须保留原始宽高（含等于上限），不因码率、BPP 或编码格式自动缩小；只有超过最大边才允许按现有尺寸优化算法缩放。避免无意义放大、升帧及重复编码。编码后验证真实容量，必要时自动调整重编码。保证音画同步和色彩信息；尽可能保留 HDR，不允许无提示转 SDR。默认优先硬编。小文件、H.264 等合适场景才考虑软编，且必须预计总耗时不超过 180 秒、速度不低于 1 倍实时、存在实际质量或压缩效率收益。任一不满足优先硬编。硬件不支持或失败时明确可追踪回退。

## 性能预测
不是 FFmpeg 外壳。CPU 综合单核、多核及并行收益、架构/指令集、编码器线程扩展效率、编码格式/预设、分辨率/帧率/位深；初始参考 i5-13600K、Ryzen 7 5800H。可信公开数据和实机 Benchmark 建立跨型号预测，不以核心数或总跑分线性换算。GPU 综合架构、编码引擎代际和数量、格式及位深支持、分辨率与预设、解码/缩放/传输开销；初始参考 RTX 4080 16GB、T600 4GB。不用游戏性能或 CUDA 核心数量简单推算。

## Benchmark 与学习
独立 Benchmark、标准素材可重复可比较，收集性能、画质、码率、容量偏差。独立版本化数据文件，官方训练数据随发行并支持在线更新；本机实际编码修正预测，本地与官方分开，更新不得覆盖本地数据。数据不足采取保守预测，不伪造精确结果。

## 工程纪律
从第一天维护 AGENTS.md、自动测试和发布规范。重点路径 Unicode/特殊字符、参数传递、大文件/超长视频、磁盘空间、任务取消/子进程残留、临时清理、同步、失败回退、配置兼容、UI 阻塞、重复硬件检测。强制回归文件名：小K 的鹅腿坟场 & (黑洞) ^ % !.avi。关键决策有日志、测试依据、可解释。每阶段验收并更新总任务卡后再进入下一阶段；不赶进度，不提前堆功能。
