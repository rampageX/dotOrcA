# S06 编码流水线及失败回退

核心入口为 `orca_core::pipeline::encode`。使用 S01 媒体探测、进程树管理及硬件快照，保留 S04 原始预算错误。先对选中路线执行 24 帧以内的实际源短片预检，使用实际输出尺寸、位深、codec、码率控制、VFR 和色彩参数，并重新探测封装结果。完整编码必须由 S05 的 `ready_route()` 放行。每轮降码率重做预检。编码器失败及该路线的输出约束失败可以进入下一条路线。取消、磁盘不足、进程超时、源或封装公共故障终止任务。观察接口提供候选路线、证据及回退原因。

输出为 MP4，音频为 AAC。验证所有视频帧的 PTS 序列和末帧时长（可读时），保留位深、显示宽高比、颜色标签、显示矩阵及 FFprobe 可识别的 HDR 静态元数据。检查各音轨声道、采样率、布局、起止时间、采样总数，拒绝显著时间间断，容许一帧 AAC 加两毫秒封装时间戳舍入差。完整扫描以有界汇总方式处理帧与包。Dolby Vision、HDR10+ 等可识别的动态 HDR 一律拒绝，此门禁依赖 FFprobe 解复用和解码器公开的元数据。不能验证的路由或媒体约束会明确失败。

临时输出位于目标目录下的独占子目录。每次封装关闭并通过验证后才读取最终字节数。超限最多重编码二次，只压低视频码率。发布前同步文件数据，Windows 在同一卷内原子移名且拒绝覆盖，其它平台发布时创建硬链接。源文件或已有同名目的文件受保护。失败或取消清理本任务的暂存文件。

生产 ETA 契约分开记录初始化及尾部、持续生产吞吐、预检与验证开销。吞吐覆盖实际解码、缩放、视频编码、音频和封装，输出上下界。无匹配且已独立校准的证据时返回未知，S09 负责校准。S06 保留 S05 默认硬编策略，GUI 接入留在其原定阶段。

## 验收

S06 CI 实际运行软件回退、特殊路径 AVI、10-bit HLG VFR 及音频偏移（HEVC、AV1）、PQ 静态 HDR、同名拒绝、源路径保护及取消清理。Linux 另以 `/dev/full` 触发 FFmpeg 实际写失败。S00–S03 CI 随 core 公开入口改动运行。Windows 使用独立 32 MiB NTFS 虚拟磁盘，在正式编码时写满并验证任务失败、源文件保护和暂存清理。物理 GPU 编码另行验收。
