# S09 实机、性能与兼容性验收

以 S08 合并并记录验收后的 main 为基线。验证工具 orca-verify 独立于 GUI，走同一生产编码入口、路线门禁、容量上限与原子发布。它不写学习库。JSON 记录源文件和工具 SHA-256、适配器与驱动、实际候选路线、失败和回退、阶段时间戳及最终字节数。工具在计时前读取并计算源文件散列，因此报告属于可能已预热的文件缓存；core_elapsed_ms 包含探测、预检、重试、验证及发布，排除入口外的散列与 GUI 学习写入。错误详情可能包含路径，分享前可检查。退出码 0 为生产发布且证据文件未变，1 为生产失败或输入变动，2 为参数或验证工具自身错误。

## 使用手边的机器做首轮验证

在手边任意一台 Windows 机器解压到可写目录，在 EXE 同级的 tools/ 放 ffmpeg.exe 与 ffprobe.exe。用有明确 BT.709 标签、8-bit、1080p 的真实 MP4 作为源，目标容量应适合源时长。有 10-bit HDR10 或 HLG 真实片段时可再跑一条，优先保持源尺寸且用不同输出名。先在空载、接电状态运行。PowerShell 示例，替换素材路径和容量，输出应为新文件：

```powershell
.\orca-verify.exe "D:\素材\SDR.mp4" ".\s09-sdr.mp4" hevc 50 1920 > s09-sdr.json
.\orca-verify.exe "D:\素材\HDR.mp4" ".\s09-hdr.mp4" hevc 100 3840 > s09-hdr.json
```

只提交实际运行的 JSON，单机即可。HEVC 硬编通过需要实际发布 encoder=hevc_nvenc；软件回退需对应 selection 和路径证据。T600 可另用 8-bit SDR 验证 AV1 回退（FFmpeg 需有 libsvtav1）。硬编失败后回退须保留原约束；如果设备缺少相关能力，只能记录该设备所获得的实际结果。HDR 只以生产校验与日志为准。

## 独立校准与兼容性

- 先按设备/驱动、工具、路线和输入特征建立拟合组。持有验证片段独立于拟合素材，同一源的不同裁切不得跨组。扩展短/长、1080p/2160p、SDR/HDR、受支持的 H.264/HEVC/AV1，分别记录空载及可重复的背景负载。固定并保留验证前生成的 ETA 上下界，再记录实际覆盖率和绝对误差。区分重试分布与单次编码吞吐；禁止以最终平均值回填预测。未有独立实测前 ETA 保持未知。
- 真实 UNC 验收用正常 SMB 共享上的输入路径（例如 `\\server\share\clip.mp4`），确认在本地目的目录发布。若验收网络输出，再执行一个独立用例，保留冲突保护结果。有现成硬件时，按实际发布路线验证 QSV、AMF 10-bit 和逐适配器归属。未覆盖的设备记为未实测，允许后续补充，无需为验收购置设备。
- 干净 Windows 验收使用无开发工具、无额外 VC++ 运行库的正常用户环境。记录 Windows 版本、首次启动及后续启动的可见窗口耗时，并在窗口静止 60 秒后记录 CPU、专用工作集与工作集。若该环境无 CJK 系统字体，另外记录中文文件在界面上的显示和拖放生产结果。当前这些物理验证均待执行。

S08 用户报告和自动回归另见 [S08.md](S08.md)。S09 保持开放，验证包由 CI 生成。

## RTX 4080 实机记录（2026-11-26）

i5-13600K、RTX 4080、驱动 32.0.16.1714、FFmpeg 9.1.git-FGS-47b92841e33b-20261122。两次均通过核心校验并发布，输入和工具散列前后相同。

| 输入 | 实际路线 | 发布字节数 / 上限 | 核心耗时 |
| --- | --- | --- | --- |
| 1080p AV1 10-bit，HDR 分类未知 | hevc_nvenc，超限后同路线降码率重试一次 | 49,673,138 / 52,428,800 | 23.423 s |
| 2160p AV1 10-bit PQ | libx265，NVENC 预检发现 24 帧时间戳序列变化后回退 | 104,108,917 / 104,857,600 | 190.049 s |

证实该机器有成功硬编发布、容量重试及保留约束的软件回退。此 PQ 样本的 NVENC 预检失败原因已定位到时间戳比较，具体差异未被报告捕获；该样本不计作 HDR 硬编通过。ETA 均为空，这两条记录不足以完成独立校准。其他实机覆盖按现有硬件记录。

## 当前生产策略

默认硬件编码。若没有兼容的硬件路线，任务明确报错，保留实际预检及编码失败原因，不自动转 CPU 编码。上文 x265 回退属于更改前的行为。主动软编仍须满足可信全任务 ETA ≤180 秒和速度 ≥1×，当前生产入口没有此证据。
