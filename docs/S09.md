# S09 实机、性能与兼容性验收

以 S08 合并并记录验收后的 main 为基线。验证工具 orca-verify 独立于 GUI，走同一生产编码入口、路线门禁、容量上限与原子发布。它不写学习库。JSON 记录源文件和工具 SHA-256、适配器与驱动、实际候选路线、失败和回退、阶段时间戳及最终字节数。工具在计时前读取并计算源文件散列，因此报告属于可能已预热的文件缓存；core_elapsed_ms 包含源信息探测、路线选择、编码、容量重试及发布，排除入口外的散列与 GUI 学习写入。错误详情可能包含路径，分享前可检查。退出码 0 为生产发布且证据文件未变，1 为生产失败或输入变动，2 为参数或验证工具自身错误。

## 使用手边的机器做首轮验证

在手边任意一台 Windows 机器解压到可写目录，在 EXE 同级的 tools/ 放 ffmpeg.exe 与 ffprobe.exe。用有明确 BT.709 标签、8-bit、1080p 的真实 MP4 作为源，目标容量应适合源时长。有 10-bit HDR10 或 HLG 真实片段时可再跑一条，优先保持源尺寸且用不同输出名。先在空载、接电状态运行。PowerShell 示例，替换素材路径和容量，输出应为新文件：

```powershell
.\orca-verify.exe "D:\素材\SDR.mp4" ".\s09-sdr.mp4" hevc 50 1920 > s09-sdr.json
.\orca-verify.exe "D:\素材\HDR.mp4" ".\s09-hdr.mp4" hevc 100 3840 > s09-hdr.json
```

只提交实际运行的 JSON，单机即可。NVIDIA HEVC 硬编通过需要实际发布 encoder=hevc_nvenc。FFmpeg 失败时保存报告即可，软件路线不进入生产任务。

## 独立校准与兼容性

- 先按设备/驱动、工具、路线和输入特征建立拟合组。持有验证片段独立于拟合素材，同一源的不同裁切不得跨组。扩展短/长、1080p/2160p、SDR/HDR、受支持的 H.264/HEVC/AV1，分别记录空载及可重复的背景负载。固定并保留验证前生成的 ETA 上下界，再记录实际覆盖率和绝对误差。区分重试分布与单次编码吞吐；禁止以最终平均值回填预测。未有独立实测前 ETA 保持未知。
- 真实 UNC 验收用正常 SMB 共享上的输入路径（例如 `\\server\share\clip.mp4`），确认在本地目的目录发布。若验收网络输出，再执行一个独立用例，保留冲突保护结果。有现成硬件时，按实际发布路线验证 QSV、AMF 10-bit 和逐适配器归属。未覆盖的设备记为未实测，允许后续补充，无需为验收购置设备。
- 干净 Windows 验收使用无开发工具、无额外 VC++ 运行库的正常用户环境。记录 Windows 版本、首次启动及后续启动的可见窗口耗时，并在窗口静止 60 秒后记录 CPU、专用工作集与工作集。若该环境无 CJK 系统字体，另外记录中文文件在界面上的显示和拖放生产结果。当前这些物理验证均待执行。

S08 用户报告和自动回归另见 [S08.md](S08.md)。S09 保持开放，验证包由 CI 生成。

## 生产链路简化

用户确认以 FFmpeg 的生产执行结果为准。仅探测源容器和流信息，以及读取可用硬件和 FFmpeg 编码器列表。直接执行所选硬件编码器，取消试编码、源和成品的解码扫描、逐帧时间戳比较。FFmpeg 失败时原样保留诊断，任务退出。仅超容量时允许原路线降码率重试。发布前按实测字节数验收，输出仍原子发布且不覆盖同名文件。

流级标记为隔行时使用 BWDIF 逐场输出（25i → 50p），逐行保留原节奏。PQ/HLG 保留原位深、传递函数、色域和矩阵，元数据随 FFmpeg 编码链路传递。已识别的动态 HDR 仍需受支持的处理路线。生产结果不再声明逐帧验证或完整动态元数据扫描。

输出 MP4 选取首个非封面视频、全部音轨、可转 mov_text 的内嵌文本字幕。字幕样式可能简化，外挂 SRT、图形字幕及附件不随 MP4 输出，TS 数据流不参与转码。截图中的独立 SRT 不是视频任务。以上是支持边界，截图里的真实素材没有在 CI 中逐一复刻。

## 队列显示补齐

源大小由独立后台线程读取文件元数据，不读取文件内容、不启动 FFmpeg；未返回时显示 reading，无法读取时显示 unknown。等待任务也可更新，读取时不持有队列锁，关闭窗口不等待可能阻塞的网络元数据读取。源大小、目标容量和成品大小明确区分，显示采用二进制单位。重试次数保留到后续编码和终态，重试阶段清除上一轮进度。编码失败保留已捕获的 FFmpeg 诊断，详情优先显示，长诊断展示首尾并提示查看任务日志。FFmpeg 的既有有界 stderr 捕获限制不变。新增队列及界面桥接单元测试；本次不修改生产编码链路或重新声明实机验证通过。
