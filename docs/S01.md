# S01 — implementation and acceptance

Scope: pure Rust media/process/hardware API and developer CLI, no GUI, prediction, encoding decisions or production pipeline.

- Media: ffprobe JSON, actual file length u64, integer microseconds, exact rational rates, all streams and raw side data. Unknown is explicit. PQ/HLG and DOVI stream metadata, SDR only when a known SDR transfer is present. HDR10+ dynamic frame metadata is not exhaustively scanned; PQ is not a claim of HDR10 certification.
- Windows process: Command native argv, absolute executable, no shell; CREATE_SUSPENDED, associate private kill-on-close Job Object, then resume initial thread using Toolhelp. Failure to associate/resume is fail-closed. Both pipes drained concurrently, bounded capture, nonzero exits, cancellation and timeout. Linux process group implementation is a CI development equivalent, not a Windows acceptance substitute.
- Hardware: present display adapters and driver versions via SetupAPI, FFmpeg version/encoder registration, three-frame 256x256 strict-format probes (NVENC/QSV/AMF). A successful test is evidence for that exact backend/default device/bit depth, not every adapter, resolution, profile, HDR metadata mode or performance. A failure is not proof of permanent hardware absence. Cache is in-memory, version/driver/tool keyed. Persistent benchmark/learning remains later.
- Developer console CLI only; tools are external and not redistributed. No run-time scripts. Default paths relative to the EXE or explicit absolute paths.
- CI and actual Windows RTX/T600 evidence must be recorded separately. S01 remains open until actual acceptance. No release/merge at this point.

- First CI run 45777249585 Linux: 5 unit tests and process self-test passed. Cargo.lock generated on CI and committed without manual dependency/checksum guesses. Final CI uses --locked only. Hardware probes also cover H.264 10-bit; failed evidence has a 60s in-memory TTL, stable evidence lasts for the unchanged complete fingerprint. CPU name from read-only Windows registry, adapter inventory failure explicit. No production configuration or persistent learning data.

- Windows process runner rejects non-.exe tools before launch (Rust may otherwise invoke cmd.exe for batch files). CI tests prelaunch cancellation and batch rejection. Actual UNC share access and disk-full during output encoding are not simulated by argv tests; real UNC verification remains outstanding, and disk-full/transactional output cleanup belongs to S06 where output writing is implemented. No claims of completed HDR dynamic frame metadata inspection or per-adapter GPU capability attribution.

- Windows CI runs 45777249585/45777411023: process self-test passed, real special-name AVI and long Unicode path passed. FFmpeg 9.1.0 FFV1 fixture omitted transfer/primaries in ffprobe output; the parser correctly reported Unknown and the fixture assertion failed. Switch color fixtures to 10-bit HEVC/libx265 with explicit color tags; retain all assertions. First two Windows runs are not final acceptance.

- Run 45777647759: 7 Windows unit tests and process self-test passed, real AVI/long path passed, MKV HEVC still omitted transfer/primaries. Strengthen fixture generation with frame setparams, explicit HEVC VUI/bitstream metadata and MP4 colr; assert both transfer and primaries. This is not a relaxation of the parser contract.
