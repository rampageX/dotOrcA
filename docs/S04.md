# S04 容量与画质策略

入口为 orca_core::budget。每个目标为单个最终封装文件的 u64 字节上限。plan 使用 S01 容器时长（微秒），按每条音轨每声道 64 kb/s 分配，逐轨向上取整字节，预留 4096 字节加容量的 1%（向上取整）。剩余视频预算乘 8,000,000 再除以时长向下取整，宽中间值和受检转换覆盖 u64 边界。音频分配及封装余量均为初始策略。额外流、未知声道或时长、不可表示的码率及不足预算返回明确错误。

保持指定 H.264 / HEVC / AV1、源位深、时间戳与颜色要求，能力由 S05 核实。按最长边限制：源长边不超过最大边（含相等）时保留原始宽高，不受 BPP 影响。仅当源长边超过上限时进入缩放算法，保留方向、向偶数尺寸取整；已知平均帧率时，按每像素每帧 0.05 bit 的启发式门槛逐档降分辨率，最低档仍不足则返回策略不可行。未知平均帧率仅应用尺寸上限，保留未知。此规则由 S09 用户明确修订，替代 S04 初版的无条件 BPP 降档。缩放时 S06 应保持显示宽高比（含 SAR），保留 VFR 和 HDR 元数据。

fixture_frontier 仅比较同一官方报告、同一解码哈希、同一编码格式的六秒合成素材，按实际封装字节淘汰超限点，返回实际容量及 SSIM 上非劣的观测和 PSNR。报告与 case_id 可追溯具体工具、驱动和预设。真实素材没有这些质量测量，不能外推码率曲线或主观画质、跑分排名。

S06 须在最终文件关闭后读取实际长度并调用 fits，缺失、空文件、超限均拒绝。封装验证、音画同步、重试及事务发布由 S06 实现。
