# S08 暗黑 GUI 与批量队列

Windows x64，CUI v1.5.0 固定提交和 CPU 软件渲染。将 ffmpeg.exe 与 ffprobe.exe 放入 dotorca.exe 同目录的 tools/。输入正整数 MiB（1 MiB = 1,048,576 字节），选择输出 codec 和最长边上限，拖入文件后点击 Start queued。设置在加入时按文件记录，每个文件单独应用封装容量上限。每次拖放最多 64 个文件，队列最多 256 项，可清除已完成项腾出空间。支持逐项取消和全部取消。

队列串行复用 Rust 核心的探测、预算、请求预检、保留约束、发布校验和本机学习。成品为 output/源文件名.mp4，遇到同名文件明确失败；不覆盖源文件或已有成品。终态诊断写入 logs/，学习由核心写入 data/local/。权限、工具缺失、写入故障和队列故障在界面报告。正在编码时的百分比取自 FFmpeg 已输出视频帧与 S06 已扫描源视频帧数，每次重试单独计数；预检和封装验证以阶段显示。缺乏可应用的 ETA 和最终封装容量预估时保持未知。

首屏不运行探测、网络访问、文件扫描或便携目录检查。系统 CJK fallback 在第一帧之后尝试，缺字库时保留英文界面并提示文件名可能显示缺字，路径仍以原生 Unicode 传入核心。后台更新当前任务快照，CUI 仅在交互或运行中定时唤醒。不要求系统原生移动窗口循环内持续重绘。

## 验证状态

- Linux 本地：核心测试、Rust/C 边界测试与真实 FFmpeg 批量回归。覆盖特殊文件名、不可变快照、活动任务期间加入和取消、成功发布及学习、冲突拒绝、缺失输入。
- Windows CI：使用原生 WM_DROPFILES 注入 UTF-16 批量拖放并检查 CUI → Rust 的文件名、取消和清除结果。原 S06 工作流同时包含真实 FFmpeg 批量回归。候选运行结果见本阶段 PR。
- 真实 Windows 双屏 100%–200% 混合 DPI、缺少 CJK 系统字库时的视觉表现待实机验证。
- 干净主机、独立 ETA 校准及 RTX 4080/T600 生产硬编留在 S09。
