## Matrix synthetic-sdr-v1 / schema 1
- Standard: 1280x720, 1920x1080, 3840x2160; 8/10-bit 4:2:0; 30/1 CFR; 180 frames; two synthetic sources (moving testsrc2, fixed-seed temporal uniform noise). FFV1 lossless intermediate, one generation thread, explicit color intent BT.709 limited SDR. 10-bit is converted from the 8-bit synthetic source, not native HDR or a representative natural scene. These fixtures measure controlled synthetic workload only. Do not extrapolate quality to actual film content.
- 12 encoders: x264/x265/SVT-AV1, NVENC/QSV/AMF H.264/HEVC/AV1, two backend-specific presets each. Nominal target video bitrate 2.5/5/18 Mbps, one or more serial repetitions (default 1). Presets and rate-control defaults are not equivalent across encoders. Actual container bitrate and quality must be compared, not target bitrate alone. No artificial frame-rate increase, no audio, no HDR/tonemap claims.
- Hardware probes reuse S01; skip unavailable/unverified encoder+depth with reason, not zero FPS. A small probe is not proof that a higher-resolution run will work. Actual encoding failures are separately recorded; no fallback. CPU uses FFmpeg encoder registration and real encode. Strict pixel format plus output codec/resolution/depth/frame-rate/decoded frame-count validation. GPU default device only; no claim of per-adapter attribution.
- Timing uses monotonic wall-clock from process launch through exit and pipe drain, including software decode, format conversion and mux. Excludes fixture generation, hardware detection, hashing, output probe and quality filters. A separate decode-only baseline is recorded for each reference, not subtracted from overlapping encoding work. No pure hardware-engine FPS claim. SSIM and PSNR compare aligned decoded frames at original depth; exact frame count required. PSNR infinity encoded as string "inf" (not JSON non-finite number).
- Hashes: FFmpeg data demuxer + stream-copy SHA256 for fixture bytes/tools/output; decoded reference SHA256 for cross-run comparison, with explicit frame format. Generator and FFmpeg build recorded. Compare source hash, matrix, arguments, tool build, repetition, and profile before using records. FFV1 decode workload is not a proxy for every source codec; cold/warm cache and thermal/clocks not controlled or measured. Windows OS build, total/available physical memory, AC status and active power scheme are recorded; power and temperature conditions must still be comparable.
- Record environment includes CPU, logical CPU count, GPU names/driver versions (without instance IDs), capability diagnostics, OS/architecture, FFmpeg/FFprobe build and SHA256, source SHA from CI, exact argv, bounded actual encoder logs, exit/stop state, fixture metadata and hashes, elapsed wall time, FPS, output bytes, actual container bitrate, SSIM/PSNR, status. Unknown is explicit; no fabricated observations.
- Portable defaults: tools/ffmpeg.exe, tools/ffprobe.exe, benchmark-results/ relative to EXE. Optional --ffmpeg, --ffprobe, --output, --repeats; --smoke reduces to two 320x180 12-frame fixtures, four encoder names, two presets. Smoke never training data. Unique run directory, atomic environment/fixture/per-case records, final report.json. Work files removed on normal return/failure; safe cancellation via empty cancel.flag inside run directory. Ctrl+C or power loss may leave work files; process tree is S01 Job Object managed. No source files overwritten or uploaded.
- CI smoke tests actual FFmpeg, special-character directories, 8/10-bit positive evidence, record completeness, repeated independent decoded fixture hashes and cancellation cleanup; S01 retains exact mandated AVI basename and long-path/argv tests. Windows candidate includes EXE, source SHA, compiler, lock, SHA256, PE imports, smoke report. CI results must not be treated as production hardware results.

## S03/S04 admission boundaries
- Use only measured OK records; skip is unknown/unavailable under this tested environment, never 0 FPS. No usable QSV or AMF 10-bit positive evidence; laptop AMF 10-bit diagnostic explicitly cites driver restriction. Do not infer hardware capability from a failed probe alone.
- Preserve measured pipeline throughput as software-decode/filter/mux inclusive, not pure GPU encode throughput. 4K 10-bit noise decode-only baseline 25.15 FPS desktop / 19.07 FPS laptop. Never derive pure encoder speed by subtracting overlapping elapsed times. If needed, create a separately versioned isolated measurement route rather than changing v1 history.
- Actual/target bitrate ratios desktop 0.9492–2.4750, laptop 0.9489–2.2702. Single bitrate per resolution and only 6-second synthetic clips; not a complete rate-distortion curve or real-world capacity guarantee. Compare actual bitrate and quality; do not rank as equal bitrate. Raw PSNR/SSIM are synthetic-reference metrics, not perceptual preference.
- FFprobe reports BT.709 matrix/limited range but no primaries/transfer in the fixtures. Not an HDR or complete color-tag validation. 10-bit is converted from 8-bit. One physical repetition per machine; no measured confidence interval, sustained thermals, clocks, or per-device attribution. S03 must expose uncertainty and avoid invented measurements; real content, additional repetitions and independent validation as needed. S09 deferred positive QSV, AMF 10-bit and per-adapter attribution remain open.
- Raw reports contain local paths and logs; no raw upload or telemetry. User-provided reports are the authoritative measured dataset; no prediction/self-learning/decision/GUI changes in S02. S03 may ingest the versioned schema and explicitly permitted sanitized evidence; retain provenance and separate future official observations from local data.
